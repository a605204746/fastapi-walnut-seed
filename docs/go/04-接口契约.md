# 前后端接口契约

本文是接口协议，**Go 为主后端**（Python 为辅参照，Java 未来移除）。Go 端实现细节在各模块代码注释中。

## 基础约定

- 路由前缀：`/auth`、`/system`、`/monitor`、`/common`、`/resource`
- 成功和业务失败统一返回 `{"code": int, "msg": str, "data": T | null}`
- 分页数据统一 `{"rows": [...], "total": N}`
- 认证请求头：`Authorization: Bearer <token>` 与 `clientid`
- 日期时间格式：`yyyy-MM-dd HH:mm:ss`
- 雪花 ID 超出 JS 安全整数范围时序列化为字符串（`idtype.JSInt`）
- 业务错误使用 HTTP 200 + body.code；路由 404/405 和健康探针 503 使用真实 HTTP 状态码

## 认证和权限

| 端点 | 说明 |
|---|---|
| `POST /auth/login` | 登录 |
| `POST /auth/logout` | 登出（幂等，白名单内） |
| `POST /auth/register` | 注册（受配置开关控制） |
| `GET /auth/code` | 图形验证码 |
| `GET /auth/tenant/list` | 租户下拉 |
| `GET /system/menu/getRouters` | 前端动态路由 |
| `GET /system/user/getInfo` | 当前登录用户信息 |

菜单权限串采用 `模块:实体:操作` 格式（如 `system:user:add`）。前端隐藏按钮不是权限控制，后端必须再次校验。

## Golden 契约（语义级，Go 自有）

**事实源：`api/golden/`**（2026-11-20 冻结，Go 自有，不再从活 Python 再生成）。`api/openapi/` 保留为历史 Python 导出，`make contract-export` 仅作参照复现。

冻结的是**语义**而非字节：

- 冻结：路由面、信封 `{code,msg,data}`、字段名（驼峰）、code 数值语义、null 恒出现、字段存在性
- 豁免：JSON 键序（diff 的 canon 已 sort_keys）
- 校验 msg：按 i18n 策略——仓库根 `scripts/contract/diff_system.py` 与 `diff_contract.py` 的 `MSG_SEMANTIC=True` 对 code=400 信封放宽 msg 精确比对（仍校验非空且无 Pydantic 英文残留）；置 False 回退严格模式

`test/contract/routes_inventory_test.go` 读 `api/golden/routes.txt`，`TestNoInventedRoutes` 仍是硬门禁：Go 出现基线没有的路由 → 测试失败。**125 条全覆盖（0 豁免）**——`/docs`、`/docs/oauth2-redirect`、`/redoc` 已由 `common/docs` 模块托管；`/openapi.json` 与 `/resource/websocket` 属"Python 有但 OpenAPI 不导出"的 invented 豁免。

## 接口文档 UI

Go 服务自带文档端点（`internal/module/common/docs`，对应 Python `register_docs`）：

| 端点 | 内容 |
|---|---|
| `GET /docs` | Swagger UI（可交互试调） |
| `GET /redoc` | ReDoc（阅读友好） |
| `GET /openapi.json` | OpenAPI 3.1 spec（冻结契约 `api/golden/contract.json`，main.go `go:embed` 注入，自包含二进制） |
| `GET /docs/oauth2-redirect` | Swagger UI OAuth2 回跳页 |

启动后浏览器开 `http://localhost:8011/docs`。Swagger UI / ReDoc 资源走 **CDN**（轻量托管，查看时需联网）；离线环境需改本地静态 bundle（Python 端用 `static/swagger/`）。spec 是冻结契约基线，变更须先评审更新 `api/golden/`。

## 参数校验（阶段 4 惯用化）

JSON body 绑定统一走 `bindx.BindJSON(ctx, body, &req)`：

- 请求结构体声明 `validate` tag（required/notblank/min/max/email/oneof/自定义）+ `label` tag（中文业务名）
- validator 全量收集字段错误（声明序），`validatex.FormatI18n` 按 `Accept-Language` 出文案（`i18nx/messages` 的 `validation.*` 键）
- 自定义业务规则（密码复杂度/邮箱/手机号正则）经 `bindx.RegisterTag` 注册，逻辑逐字复刻原实现
- 空/空白 body 视为空对象（触发必填校验）；service 消费的 In 结构由 Decode* 映射，业务层零感知

相对 Pydantic 兼容期的**刻意语义演进**（前端零代码改动，仅用户可见文案变化）：

| 项 | 旧（Pydantic 复刻） | 新（惯用） |
|---|---|---|
| 类型错误文案 | 英文原文 "Input should be a valid string" | i18n "{label}必须是字符串" |
| lax 强转 | "3.0"/"1_0" 接受为整数 | **保留**（2026-11-21 恢复）：雪花 ID 回传是字符串，Python `model_validate_json` 接受，严格拒绝曾导致全部更新类接口 400；实现见 `bindx.laxJSONBody`，边界以实测 golden 钉住 |
| 空数组必填 | 部分模块 nil-only 检查放行 [] | required,min=1 拒绝（对齐 Python falsy） |
| 多错误收集 | 类型错误也参与拼接 | JSON 类型错误短路（encoding/json 限制）；校验级错误仍全量拼接 |
| 长度文案 | "String should have at least N characters" | "{label}长度不能少于N个字符" |

**新模块从第一天用 tag 范式**（见 08-新增CRUD模块）；query/form 绑定（BindQueryParam/BindExportParam）仍走 crudx/bindx 查询 cluster，不在此列。
