  ```bat

  docker pull docker.m.daocloud.io/docker/dockerfile:1
  ```

  已死的别试：dockerproxy.cn / docker.1panel.live / hub.rat.dev / dockerpull.org /
  docker.unsee.tech / mirror.gcr.io / public.ecr.aws / docker.mirrors.ustc.edu.cn。

### 5.2 契约层面（最容易写错的地方）

- **雪花 ID 是条件序列化，不是全转字符串**。`|v| >= 9007199254740991` 才转字符串；
  `status`/`sex`/`total` 等小整数**必须保持数字**。用 blanket `json:"id,string"` 会让
  前端所有 `=== 0` 判断失效。实现见 `pkg/idtype/jsint.go`，计划 §9.1。
- **登录响应是 snake_case**（`access_token`），**验证码响应是 camelCase**（`captchaEnabled`）。
  不一致是 Python 端的既有事实（前者返回裸 dict，后者走 `model_dump(by_alias=True)`），
  不能"顺手统一"。
- **健康探针字段是 snake_case**（`latency_ms` / `uptime_seconds` / `disk_usage`）。
- **`dept_name` / `dept_category` 在 JWT claims 里是 `""` 不是 `null`**。
- **校验错误文案必须是 Pydantic 原文**（`Field required`、
  `String should have at least 2 characters`，含英文单复数），用 `pkg/validatex`。
  这个 msg 会直接展示给用户，属契约。
- **`grant_type` 校验是字符串子串匹配**（`strings.Contains`），不是 split 后精确匹配。
  Python 端 `body.grant_type not in (client.grant_type or "")` 就是这个语义。
  **契约一致性优先于代码正确性**——别"修正"它。
- **尾斜杠**：Gin 内置重定向对 GET 用 301（会被浏览器永久缓存），Starlette 全用 307。
  已用 `bootstrap.slashAwareNoRoute` 统一改成 307。新增路由不需要额外处理。
- **模型客户端默认值属契约**（2026-11-03 实测抓到两次）：Python 端 SQLAlchemy
  `mapped_column(default=...)` 会给新增时**未传**的字段补值——dept 是
  `status='0'`、`parent_id=0`、`ancestors=''`、`dept_name=''`、`order_num=0`；
  dict 数据表是 `dict_sort=0`、`dict_label=''`、`dict_value=''`、`dict_type=''`、
  `is_default='N'`（而 `css_class/list_class/remark` 默认 None → NULL）。
  ⚠️ dict **类型表相反**：构造器原样传 None → 插 NULL 不吃默认值。
  Go 侧不在 service 层镜像就会插入 NULL（GORM 对 nil 指针字段写 NULL，
  不吃 DB server default）。抄五件套前先逐字段看一遍对标模型的 default。
- **RepeatSubmit 的防重键含请求体**：窗口内重发同一 body（哪怕第一次是校验失败）
  会被「不允许重复提交，请稍候再试」拦下，两端行为一致。契约脚本里
  两条断言不要复用完全相同的 body（diff_dept 第 7 组用 orderNum 87/88 区分）。

### 5.3 Go 特有的坑

- **nil slice 序列化成 `null`**，Python 返回 `[]`。repo 层查询后统一兜底。
- **GORM 复合字面量不能写嵌入结构的提升字段名**（`CreateBy` 在 `modelx.BaseModel` 里），
  必须逐字段赋值：`u.CreateBy = &x`。
- **`multiStatements=true` 只能用于迁移专用连接**（`databasex.OpenForMigration`）。
  加到应用主 DSN 上会让 SQL 注入可以拼接执行多语句。
- **`gorm.ErrRecordNotFound` 是正常业务结果**，已在 `databasex.newLogger` 里
  `IgnoreRecordNotFoundError: true` 静默掉，别再改回去。
- **共享可变状态要加锁**（计划 R8）。Python 单事件循环下的模块级全局，
  在 Go 里是真并发。`idgen.SetDefault` 已用 RWMutex，新加全局状态记得同样处理。
- **`rsa.DecryptPKCS1v15` 第一个参数是 `io.Reader`**（blinding 用），不是 `(priv, ct)`。
- **AES-ECB 必须手写**（Go 标准库没有 ECB 模式）。已验证的实现在 `pkg/cryptox/aes.go`，
  **直接复用，别重写**。
- **GORM 的 `First(&scalar)` 会报 "model value required"**（2026-11-03 实测）：
  `First`/`Take` 只接受 struct 目的地；取单列标量要用 `Pluck`/`Scan`/`Row`。
  notice 的 createByName 反查用户 ID 第一版就踩了它（契约 diff 抓到 500）。
- **NOT NULL 约束冲突在 Python 端是 409 不是 500**：IntegrityError 被全局异常处理
  映射成 `code=409「数据已存在或违反完整性约束」`。notice 缺 notice_type 新增即此例；
  Go 侧要镜像成 `errs.Conflict(errs.MsgDBIntegrity)`，别包成 500。
- ★ **`Builder.authMiddleware` 必须在 `registerRoutes` 之前注入**（P3 新增）。
  `Protected()` 组在**创建时**就把中间件快照进 gin 的 handler 链，之后改字段不生效。
  这是个**静默失效**陷阱：路由注册成功、启动期审计也通过（审计只看登记表不看 handler 链），
  但请求实际不带认证。已在 `buildEngine` 里固定顺序，别调换。
- ★ **菜单建树时 `parent_id IS NULL` 必须跳过，不能当 0**（P3 新增）。
  Python 端把它归到字典的 `None` 键，而 `_build_children` 只用整数 `parent_id` 查找，
  `None` 永远取不到 = 丢弃。Go 里若写成 `ParentIDOrZero()`，会凭空多出一批顶级路由。
  这个偏差**只有 getRouters 的严格逐字节比对能抓到**，见计划 §14.4⑤。
- ★ **权限/菜单 ID 一律从 `authctx.Context` 取，不要查库**（P3 新增）。
  Python 端在登录时就把权限算好写进 Redis 会话，每次请求只读一次会话，
  **改权限后需重新登录才生效**。Go 侧"优化"成实时查库会造成两端行为不一致。

### 5.4 三端隔离（写错会串数据）

| 维度 | Go 侧的值 |
|---|---|
| 数据库 | `walnut_seed_go` |
| Redis 键前缀 | `walnut-seed-go` |
| 日志文件 | `walnut-seed-go.log` |
| 镜像名 | `walnut-seed-backend-go` |

Redis 前缀写错会导致登录态/验证码/限流计数与另两端**互相串键**。
业务代码里**禁止自己拼 Redis 键**，一律走 `cachex.Client.Key()`。

### 5.5 契约脚本层面的坑

- **urllib 不对 URL 里的中文做隐式编码**：`Request(url)` 里带裸中文直接抛
  `'ascii' codec can't encode`（diff_dept 实测）。查询串里的中文一律
  `urllib.parse.quote` 后再拼。
- **py 端「写后立即可读」有毫秒级竞态**（根因见 §6 的写后提交时机行）：
  写后读断言要对 py 加短重试窗口（diff_post 第 7 组 5 秒窗口），
  否则偶发假失败；Go 端无此窗口，不要镜像。
- **连跑 diff 脚本撞登录限流**：见 §3 的限流提示（10 次/分钟/IP）。

## 6. 已接受的偏差（不是 bug，别去"修"）

| 项 | 说明 |
|---|---|
| **JWT header 键序** | PyJWT `{"typ","alg"}`，golang-jwt `{"alg","typ"}`。token 字符串不同但**互相可验证**。三端 token 本就不要求可互换（各自独立 Redis 会话） |
| **bcrypt 前缀** | Go 生成 `$2a$`，Python `$2b$`。算法等价、互相可验（测试覆盖 2a/2b/2y）。Go 标准库无导出手段生成 2b |
| **bcrypt cost** | 新建密码用 **12**（`cryptox.BcryptCost`），对齐 Python `bcrypt.gensalt()` 默认值。种子数据里的哈希是 cost 10（历史预生成），校验侧无影响 |
| **`/ready` 探测超时** | Go 2s（可配 `HEALTH_PROBE_TIMEOUT`），Python 无显式超时（靠 POOL_TIMEOUT=30，实测约 4s）。依赖「慢但存活」时两端结论可能相反。刻意选择短超时以适配 compose healthcheck 的 `timeout: 5s`。见计划 R19 |
| **验证码图片字节** | 随机图片不可能逐字节相同，diff 脚本归一化为 `<IMG>` |
| **写后提交时机** | Python 全应用无显式 `commit()`：`db_getter` 的 `session.begin()` 在 yield teardown 提交，而 FastAPI ≥0.106 的 teardown 在**响应发送之后** → py 端写后立即可读有毫秒级窗口可能读不到；Go 在写响应前提交（正确行为）。契约脚本对 py 加重试窗口兜底（diff_post 第 7 组、diff_dict 第 6 组）。**dict 额外放大该竞态**：窗口内的读会把旧结果**写进字典缓存**（缓存污染，实测抓到），脚本用产品自带的 refreshCache 中和；**不要在 Go 端镜像这个竞态，也不要单方面改 Python 的提交时机**（全应用事务语义，影响面另评） |
| **`.env.test` 加密配置是坏的** | 512 位 RuoYi 黑名单密钥 + 与后端不配对 → `pnpm build:antd:test` 产物登录必然失败。**这是前端仓库的既有问题，三端同受影响，我没动**。见计划 §12.8 |
