# 接口加解密

> 更新日期：2026-11-04 · 适用版本：WalnutSeed v1.0

接口请求/响应体加解密（RSA + AES 混合）用于保护敏感数据传输。Go 端实现位于 `internal/pkg/cryptox/` 和 `internal/pkg/middleware/apidecrypt.go`。

## 1. 混合加密模型

RSA 包裹一次性 AES 密钥，AES 加解密 JSON 体：

- RSA-PKCS1v15 分段（加密块 `keySize/8-11`、解密块 `keySize/8`）
- AES-ECB-PKCS7（Go 标准库无 ECB，手写实现于 `cryptox/aes.go`）
- 密钥统一为 Base64 编码的 DER（公钥 SPKI、私钥 PKCS#8）

## 2. 请求方向（前端加密 → 后端解密）

```
前端：randomStr(32) 生成 AES 密钥
      ├─ AES 加密请求体
      └─ RSA(公钥) 加密 AES 密钥 → encrypt-key 请求头
        ▼
后端 ApiDecryptMiddleware（middleware/apidecrypt.go）：
      RSA(私钥) 解出 AES 密钥 → AES 解密 body
      → handler 拿到明文
```

触发条件：POST/PUT + 带 `encrypt-key` 请求头（被动触发）。

## 3. 密钥配置

```bash
# .env.dev
API_DECRYPT_ENABLED=true
API_DECRYPT_PRIVATE_KEY=<Base64 DER PKCS#8 私钥>
API_DECRYPT_PUBLIC_KEY=<Base64 DER SPKI 公钥>
```

## 4. 启动期安全校验

`internal/config/validate.go`：

- 密钥为空/无效 → `API_DECRYPT_ENABLED=false` + 告警降级（**绝不带假密钥运行**）
- prod 下密钥命中 RuoYi 公开密钥黑名单 → 拒绝启动

## 5. 互通验证

`test/cryptointerop/` 验证 Python↔Go 加解密互通：

- AES 密文逐字节比对（21 组测试向量）
- RSA 分段加解密互通（5 组）
- bcrypt 哈希互通（Go `$2a$` / Python `$2b$`，算法等价）

## 6. JWT

`internal/pkg/cryptox/jwt.go`：

- 算法：HS256（golang-jwt/v5）
- 载荷：`sub`（会话 ID）、`user_id`、`clientid`、`is_refresh`、`exp`
- 与 Python 端差异：header 键序不同（`{"alg","typ"}` vs `{"typ","alg"}`），token 字符串不同但互相可验证
