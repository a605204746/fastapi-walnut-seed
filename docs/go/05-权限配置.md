# 菜单与权限配置

> 更新日期：2026-11-04 · 适用版本：WalnutSeed v1.0

本文讲清 Go 后端的权限体系：菜单/按钮/数据三层权限如何在 Go 端实现，以及与 Python 端的对应关系。

## 1. 权限体系总览

三层模型：**菜单 → 角色 → 用户**，与 Python 端完全一致。

| 层 | 控制什么 | Go 端载体 |
|---|---|---|
| 菜单/页面 | 前端动态路由 | `GET /system/menu/getRouters` → `internal/module/system/menu/` |
| 按钮/接口 | 后端接口访问控制 | `permguard.Require("system:user:add")` |
| 数据（行级） | 同一页面里的数据行过滤 | `permx.Build(ctx, db, auth, option)` |

## 2. 功能权限（permguard）

`internal/pkg/permguard/`，对应 Python 端 `AuthPermission`。

```go
// 在 handler.Mount 中挂载
b.GET("/list", require("system:user:list"), h.List)
b.POST("", require("system:user:add"), repeat(), h.Add)
```

校验顺序：

1. 超管（`ID==1`）或持 `*:*:*` → 直接放行
2. 角色校验（`role_mode`）→ 不满足 → `errs.NotRole()`（code=403）
3. 权限码校验（`mode`）→ 不满足 → `errs.NotPermission()`（code=403）

> **启动期审计只检查认证中间件**，不检查权限守卫。漏挂权限守卫不会阻止启动，要靠契约 diff 的 403 用例兜底。

## 3. 数据权限（permx）

`internal/pkg/permx/`，对应 Python 端 `Permission` 组件。

```go
scope, err := permx.Build(ctx, db, auth, permx.UserList)
if err != nil {
    return errs.Wrap(err, errs.MsgDBFailed)  // fail-closed: 必须向上传播
}
q = scope.Apply(q)  // 追加 WHERE 条件
```

六种 `data_scope`：

| 值 | 含义 | SQL 条件 |
|---|---|---|
| 1 | 全部 | 无（短路放行） |
| 2 | 自定义 | `dept_column IN (SELECT dept_id FROM sys_role_dept WHERE role_id=?)` |
| 3 | 本部门 | `dept_column = user.dept_id` |
| 4 | 本部门及以下 | `dept_column IN (本部门 + 子孙部门)` |
| 5 | 仅本人 | `create_by = user.id` |
| 6 | 本部门及以下或本人 | 范围4 OR 范围5 |

多角色条件以 OR 连接。

### fail-closed 原则

```go
// ❌ 错误写法：等于放行全部数据
scope, err := permx.Build(...)
if err != nil { return nil }

// ✅ 正确写法：向上传播错误
scope, err := permx.Build(...)
if err != nil { return errs.Wrap(err, errs.MsgDBFailed) }
```

误用零值 Scope 的 `Apply` 也不会泄漏——denied 状态下会生成 `WHERE 1=0`。

### 两套列配置

```go
permx.Default   // create_by + create_dept（大多数表）
permx.UserList  // create_by + dept_id（用户列表按所属部门过滤）
```

## 4. 部门数据权限的特殊实现

`internal/module/system/dept/service.go` 不使用 `permx.Build`，而是手写数据权限条件，原因：

1. 过滤列是 `sys_dept.id`（自身主键），不是 `create_dept`
2. 无角色 → 不过滤（与 permx 的 fail-closed self-only 相反）
3. SELF scope → `1=0`（部门表无 create_by 列）

这是 Python 端的既有行为，Go 端忠实镜像。
