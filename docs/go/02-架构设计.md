# Go 后端架构设计

> 更新日期：2026-11-04 · 适用版本：WalnutSeed v1.0

本文讲 Go 后端框架层的设计决策与机制。改框架本身之前先读这篇；在它之上做业务开发请优先看 [新增 CRUD 模块](./08-新增CRUD模块.md)。接口协议见 [接口契约](./04-接口契约.md)。

## 0. 系统架构总览

```
main.go → cmd.Execute()
    └── bootstrap.New(cfg)
         ├── 日志初始化（logx: slog + lumberjack）
         ├── 安全校验（validate.go: 密钥/路由审计 fail-fast）
         ├── 雪花 ID（idgen）
         ├── 数据库（GORM + golang-migrate）
         ├── Redis（cachex + 键前缀）
         ├── 对象存储（storagex: S3/OSS）
         ├── SSE 管理器（ssex）
         ├── Gin 引擎 + 中间件链
         ├── 路由认证审计（audit.go）
         └── HTTP Server + 优雅停机
```

### 0.1 请求在系统中的位置

| 层次 | 代码位置 | 主要职责 |
|---|---|---|
| 中间件链 | `internal/pkg/middleware/` | Recovery → CORS → Locale → ApiDecrypt → RequestLog → CorrelationId |
| 路由层 | `internal/bootstrap/router.go` | Builder 分组、认证中间件注入、权限守卫 |
| Handler | `module/*/handler.go` | 参数绑定、调用 Service、信封响应 |
| Service | `module/*/service.go` | 业务编排、数据权限、跨模块调用 |
| Repo | `module/*/repo.go` | GORM 数据访问 |
| 基础设施 | `internal/pkg/` | envelope / errs / cryptox / permx / idtype / timex / crudx / excelx |

### 0.2 依赖方向

单向向内：`cmd → bootstrap → module → pkg → config`。模块不反向依赖 bootstrap（通过 `routex.Binder` 闭包适配解导入环）。

## 1. 响应与异常

### 1.1 统一响应信封

`internal/pkg/envelope/`：

```go
type Response struct {
    Code int    `json:"code"`
    Msg  string `json:"msg"`
    Data any    `json:"data"`  // 永不含 omitempty → 恒出现 "data": ...
}
```

- `OK(c, data)` → `{code:200, msg:"操作成功", data:...}`
- `Fail(c, msg)` → `{code:500, msg:..., data:null}`
- `Page(c, rows, total)` → `{code:200, data:{rows:[...], total:N}}`

### 1.2 异常体系

`internal/pkg/errs/`：

| 函数 | body.code | HTTP | 场景 |
|---|---|---|---|
| `New(msg)` | 500 | 200 | 业务失败 |
| `BadRequest(msg)` | 400 | 200 | 参数校验 |
| `NotLogin()` | 401 | 200 | 认证失败 |
| `NotPermission()` | 403 | 200 | 权限码不足 |
| `Conflict(msg)` | 409 | 200 | 唯一键冲突 |
| `HTTPError(404, ...)` | 404 | **404** | 框架级路由缺失 |

**核心设计**：业务异常几乎都返回 HTTP 200，真实语义在 body.code。框架级 404/405 和健康探针 503 返回真实 HTTP 状态码。

## 2. 认证与权限

### 2.1 JWT + Redis 会话

`internal/module/web/auth/middleware.go`：

1. 取 token（`Authorization: Bearer <jwt>` 或 query 参数，SSE 场景）
2. `cryptox.ParseToken` 解析 JWT（HS256）
3. 校验 `clientid` 头与载荷一致
4. Redis 会话查找（`user_session:<sid>`）
5. 组装 `authctx.Context` 写入 gin key

**滑动过期**：Redis 会话中的 active_timeout 控制不活跃失效时间，TTL 过半时同步续期。

### 2.2 permguard 权限守卫

`internal/pkg/permguard/`：

```go
b.GET("/list", perm.Require("system:user:list"), h.List)
```

- 超管（`ID==1`）或持 `*:*:*` 直接放行
- 缺失权限 → `errs.NotPermission()`（HTTP 200 + code=403）
- 启动期审计只检查认证中间件，不检查权限守卫（靠契约 diff 的 403 用例兜底）

### 2.3 permx 数据权限（行级）

`internal/pkg/permx/`：

```go
scope, err := permx.Build(ctx, db, auth, permx.UserList)
q = scope.Apply(q)  // 追加 WHERE 条件
```

六种 `data_scope`（1-6），多角色 OR 连接。**fail-closed**：组件出错 → `1=0`（拒绝所有），不是放行。

## 3. 中间件链

`internal/bootstrap/router.go` 的 `registerMiddleware`，从外到内：

| # | 中间件 | 条件 | 职责 |
|---|---|---|---|
| 1 | Recovery | 恒挂 | panic 兜底，渲染信封体 |
| 2 | CORS | 恒挂 | prod 读 AllowedHosts，否则 `*` |
| 3 | Locale | 恒挂 | Accept-Language → i18n |
| 4 | ApiDecrypt | `APIDecryptEnabled` | RSA 分段 + AES-ECB |
| 5 | RequestLog | 恒挂 | 计时 + 脱敏 |
| 6 | CorrelationId | 恒挂 | X-Correlation-ID |

## 4. 数据层

### 4.1 GORM + 迁移

- ORM：`gorm.io/gorm` v2，连接池参数显式配置
- 迁移：`golang-migrate`，`migrations/*.sql` 文件，**生产禁用 AutoMigrate**
- 种子数据：`seed/mysql_data.sql`，幂等播种

### 4.2 五件套模式

每个业务模块五个文件：

```
module/system/post/
├── model.go    # GORM 实体
├── dto.go      # 入参/出参（camelCase，JSInt，JSONTime）
├── repo.go     # 数据访问
├── service.go  # 业务逻辑
└── handler.go  # HTTP 端点 + Mount
```

### 4.3 类型约定

- 雪花 ID：`idtype.JSInt`（条件序列化，`|v| >= 9007199254740991` 才转字符串）
- 时间：`timex.JSONTime`（`yyyy-MM-dd HH:mm:ss`，零值输出 `null`）
- 状态/标志：`CHAR(1)` 字符串（`"0"` 正常 / `"1"` 停用），不是整数
- 可空列：Go 用指针（`*string`），零值无法区分 NULL 和空串
